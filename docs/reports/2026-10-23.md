# Weekly tune-up: week to Oct 23, 2026 (0.12.0)

This is the public summary of one weekly review of Quality Router. The review reads the week's local session transcripts and the router's own records, replays the week's prompts through the rules offline, and makes changes only where the data supports them. Nothing is sent to a model to measure it.

Project names, prompts and personal usage figures are left out. Prompts quoted here are paraphrased. Costs are shown as shares of the week's cost at list prices, and every saving is a cache-aware estimate.

**In short:** the biggest gap this week was in how the router splits work into tasks, not in which model it picks. A status question like "tests still running?" started a new task, which was judged as a plain question (middle tier), and the work that followed rode on that judgement. 0.12.0 fixes this and three smaller issues. In the replay, routing goes lower in no case.

- **Version:** 0.12.0 (`769e3c4`).
- **Checks:** all 256 tests pass; the type check and `claude plugin validate --strict` are clean.
- **Data:** six days of sessions, about 29,000 main-conversation requests across about 20 sessions. Opus 5.5 answered about 97% of them.

## Changes in 0.12.0

**Tasks**
- **A question about work under way carries the task on**, as "keep going" does. Examples: "tests still running?", "is it done yet", "build 22 finished?", "how is the audit going?", "how many are left?", "what next", "what should we do next".
  - It keeps the task's tier and risk.
  - It never runs below what it would as new work: one the rules can't read ("build finished?") still gets the strong tier.
  - Replayed on the week's 344 prompts: the task tier rose for 4,821 requests and **fell for none**.
- **Curly apostrophes** (smart punctuation) read like plain ones: "doesn’t work" is a bug report, and "what’s next" is a follow-up.

**High risk**
- **More store steps are high risk:** "push build" without a number, "submit 2.1.4", adding or swapping the build on a version, *What to Test* notes, expedited-review and status-update requests to App Review.
- **What sits behind a paywall** counts as payments.
- Replayed on the week: 13 prompts are newly high risk, all real release or paywall steps, with no false positives.

**Compaction**
- **A refused auto-compaction is retried** at the next turn end instead of waiting 10 minutes, as the README already promised.

## Recommendations for users

- **Restart long-running sessions** after updating, so they load 0.12.0. Older copies miss these fixes, and the oldest can overwrite shared settings (the settings guard puts them back).
- **Consider a smaller auto-compact window.** With `CLAUDE_CODE_AUTO_COMPACT_WINDOW=300000` (instead of 350000), Claude Code compacts at about 267k instead of 317k. Simulated on this week's sessions: about 209 more compactions and an estimated 8% lower cost. 250000 would save an estimated 16%. Checks after compactions failed no more often than elsewhere, but step down one notch at a time.
- **Move sessions on older models to the current one** where the work allows; it re-caches once.

## Limitations

- **The task simulation is approximate.** It shows what the rules ask for. It leaves out the classifier, escalations and the switching hold (which only raise or keep a tier), so it is not exactly what would have run.
- **Savings and costs are estimates at list prices.** The compaction figures are counterfactual; they assume the same requests would have followed.
- **Raising status questions costs a little more** where switching would otherwise have paid. Most of those requests already ran on Opus, so the cost is small. It wasn't estimated separately.
- **The Sonnet/Opus check comparison rests on one session** and a few dozen Sonnet checks.
- **One user's week.** These are one person's sessions, mostly mobile-app work; other workloads may differ.
